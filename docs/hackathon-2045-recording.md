## 4. 录屏主叙事：全链路

**全链路**在评委侧应呈现为 **一条因果链**，且 **链下（应用/API）**、**链上（HashKey 测试网）**、**商户可见性** 能对应 **同一 intent**，而不是三段无关操作。

建议口述/字幕主线：

**创建意图 → 链上入金（主路径）→ 后端/状态确认 → 托管可见 → 用户签 → 商家签 → 提交释放 → Blockscout 可查 →（可选）到期退款**

每一大步尽量同时出现（或 2 秒内切到）：**当前步骤名**、**intentId**、**HashKey Testnet / 133**、**Explorer 或 tx 短哈希**。

---

## 5. 主路径策略：以链上入金为主，Gateway 为加分

- **主演示**：链上 **授权 + 存入托管**，再走 **双签释放**；全链路录屏以这条为准。
- **Gateway（HashKey 收银台 / `payment_url`）**：作为 **30～60 秒加分附录**（单独片段或片尾），**有凭证再录**；主片中用 **一句** 说明即可，例如：「链下收银为可选路径；本演示以链上入金为准。」
- **主片不要**与 Gateway 并排抢戏，避免评委误以为必须走收银台才能完成 PayFi 叙事。

---

## 6. 推荐片长与段落结构（主片约 4～6 分钟）

| 段落 | 时长 | 内容 |
|------|------|------|
| 开场 | 15～25s | 项目名、**HashKey Chain Testnet · Chain ID 133**、演示 URL |
| A | 45～90s | 用户端：连接钱包、切网、**创建意图**、展示 **intentId** |
| B | 60～120s | **链上入金**：授权 → 存入托管 → 确认 → **Explorer 入金 tx** |
| C | 30～45s | **商户侧或 Webhook 可见性**：商户控制台或意图详情显示已托管 |
| D | 90～150s | **双签释放**：用户签 → 切商家钱包 → 商家签 → 提交 → **Explorer release tx** |
| E | 30～60s | **退款**（若周期允许）或说明「到期可退 + 架构支持」 |
| 收尾 | 15～20s | Blockscout：**合约 + 典型交易**；Repo / 文档 |

**备用**：另录一条 **约 60s、无解说纯操作**，供剪辑或平台时长限制使用。

**Gateway 加分段（非主路径）**：单独附录；展示 `payment_url` 打开收银台或「凭证开通后此处可用」。

## 7. 操作顺序（减少重录）

1. 浏览器只开必要标签；钱包 **预置 HashKey 测试网** 与测试资产。
2. **用户钱包** 完成：创建 → 入金 → 用户签。
3. **再切商家钱包**（或另一浏览器配置）：商户端签名与提交。
4. **收尾** 统一到 Blockscout 从合约页点进 **1～2 笔 tx**，比边操作边找哈希更稳。

钱包频繁切换处，UI 上 **停顿 2 秒** 或显示 **「请切换商家钱包」**，便于剪辑与观众理解。

## 8. 分镜必备元素与常见漏拍

- **必含**：步骤标题、**intentId**、**133**、**Blockscout / tx**（至少各出现一次清晰特写）。
- **易漏**：只录链上 **未录商户/Webhook**；或只录 API **未录链上 tx**。建议 **每个状态变化** 跟一个 **外部可验证点**（Explorer 或商户屏一行日志）。

---

## 9. UI 与录屏对齐（实现时的检查清单）

- **页眉/横幅**：`HashKey Chain Testnet · 133`；可选 **PayFi** 与 **HSP / hashfans 手册链接**（新窗口）。
- **分步向导**：步骤顺序与主路径一致，例如 **创建 → 链上入金 → 确认与托管 → 用户签 → 商家签 → 结果 →（退款）**；Gateway 放入 **「可选」** 折叠或片尾说明。
- **用户签完成后**：强提示跳转 **商户端**（`/merchant`），全链路故事不断裂。
- **错误提示**：人话 + 下一步（如错链 →「请切换到 HashKey Chain Testnet」），减少补录。
- **构建策略**：HashKey-only 时 **不出现 Base Sepolia / Circle 等另一测试网默认文案**（与部署环境一致）。
